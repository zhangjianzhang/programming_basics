01 从单文件到模块

程序能运行，不代表代码组织得合理。

课件第 3–6 页
业务情境运营人员每天读取订单、清洗数据、计算实付金额、按渠道汇总，再保存报表。如果所有功能都放在 main.py，需求增加后会发生什么？

先观察：一个文件承担全部工作

main.py read_orders(path) clean_orders(orders) calculate_payables(orders) summarize_by_channel(orders) save_report(summary, path)

读取、清洗、计算、汇总、输出都挤在同一个文件里。请选择一种业务变化，看看最直接需要关注哪里。

维护影响需要在较长的 main.py 中寻找并修改计算代码。计算逻辑与其他职责混在一起，定位成本更高。

按职责拆分之后

order_project/ ├─ main.py ├─ order_utils.py └─ report_utils.py
main.py

组织处理流程，调用其他文件提供的函数。

order_utils.py

清洗订单、校验业务规则、计算实付金额。

report_utils.py

汇总订单，并将统计结果写入报表。

拆分不改变业务逻辑，改变的是代码的组织方式：每个文件负责一类清晰任务。

模块、包和库不是一回事

模块 Module

一个 .py 文件，保存相关函数、变量和语句。

包 Package

组织多个模块的目录，通常包含 __init__.py。

库 Library

可复用代码集合的较宽泛称呼，可以包含模块和包。

02 导入模块并调用

模块文件名决定模块名；导入后通过名称找到其中的函数。

课件第 7–8 页
任务把订单金额计算函数放进 order_utils.py，然后在 main.py 中使用它。

模块文件：order_utils.py

"""订单数据校验和计算工具。""" def calculate_payable(amount, discount_rate): if amount < 0: raise ValueError("订单金额不能为负数") if not 0 <= discount_rate <= 1: raise ValueError("折扣率必须在0和1之间") return amount * (1 - discount_rate)

文件名是 order_utils.py，导入时使用模块名 order_utils，不写扩展名。

切换导入方式

import order_utils payable = order_utils.calculate_payable(640.0, 0.15) print(f"实付金额：{payable:.2f}元")
运行结果实付金额：544.00元函数来源清楚，调用时带上模块名，优先推荐。

为什么不推荐星号导入？

from order_utils import *
多个名称直接进入当前程序，阅读代码时难以判断函数来源，也可能覆盖已有名称。优先使用明确的导入方式。

03 模块被导入时会发生什么

__name__ 可以区分模块是直接运行，还是被其他程序导入。

课件第 9 页
问题把测试代码写在工具模块末尾，为什么从 main.py 导入时不会自动打印测试结果？

模块末尾的保护条件

if __name__ == "__main__": result = calculate_payable(640.0, 0.15) print(f"测试结果：{result:.2f}元")
此时 __name__ 的值
"__main__"
测试代码是否执行执行当前文件是程序入口，条件成立。

导入并不是什么都不做

Python 会执行模块最外层的语句。因此，可复用模块的最外层通常放函数定义、常量和必要的初始化代码；不要把不希望导入时发生的测试或演示操作直接放在最外层。

这段条件让函数既能被其他程序安全导入，也能在直接运行模块时执行简单测试。

04 模块查找与常见错误

导入失败时，先检查 Python 实际在哪里找模块。

课件第 10–12 页

同一项目文件夹中的两个文件

order_project/ ├─ main.py └─ order_utils.py

当 main.py 在项目目录中运行时，可以直接写：

import order_utils
1
Python 内置模块
首先检查 Python 自身提供的内置模块。
2
程序所在位置
运行 .py 文件时，查找脚本所在目录；Notebook 中查找当前工作目录。
3
Python 环境中的目录
继续查找标准库和当前环境中已安装的第三方库。

选择遇到的问题，练习排查

排查路径检查模块名、文件名和工作目录确认模块位于 Python 的查找范围中。

两个有用的检查语句

from pathlib import Path import order_utils print(Path.cwd()) print(order_utils.__file__)

Path.cwd() 查看当前工作目录；__file__ 查看实际导入的模块文件位置。

Notebook 通常会保留已经导入的模块。修改文件后，可重新启动内核，或使用 importlib.reload(order_utils) 重新加载。

避免模块名称冲突

不要把自己的文件命名为 random.py、json.py 或 csv.py 等标准库模块名称，否则可能遮蔽同名模块。

import importlib importlib.reload(order_utils)

06 第三方库与运行环境

能导入不等于一定安装成功；关键是安装位置和运行代码的解释器是否一致。

课件第 15–18 页

标准库与第三方库

标准库

随 Python 一起提供，通常可以直接导入，例如 csv、pathlib、statistics。

第三方库

由其他开发者提供，通常需要安装，例如 pandas、openpyxl、requests。

import pandas as pd orders = pd.read_csv("data/orders.csv") average = orders["金额"].mean()

选择安装方式

%pip install pandas

Notebook 中的 %pip 面向当前内核运行安装命令。

为什么建议每个项目使用独立环境？

macOS / Linux
python3 -m venv .venv source .venv/bin/activate
Windows PowerShell
py -m venv .venv .venv\Scripts\Activate.ps1

不同项目可以使用不同版本的第三方库，减少升级一个项目时影响其他项目的情况。

激活后，终端中的 python 和 pip 会指向这个虚拟环境。

让别人能够重建项目环境

记录当前依赖
python -m pip install pandas python -m pip freeze \ > requirements.txt
在新环境恢复
python -m pip install \ -r requirements.txt python -m pip check

共享项目代码、数据说明和 requirements.txt；通常不提交或共享 .venv 目录，其他人在自己的电脑上重新创建。

三个文件如何协作？

order_utils.py
def calculate_payable(order): amount = float(order["金额"]) rate = float(order["折扣率"]) if amount < 0: raise ValueError("订单金额不能为负数") if not 0 <= rate <= 1: raise ValueError("折扣率必须在0和1之间") return amount * (1 - rate)
report_utils.py
def summarize_by_channel(orders): totals = {} for order in orders: channel = order["渠道"] totals[channel] = ( totals.get(channel, 0.0) + order["实付金额"] ) return totals
main.py：组织流程
from pathlib import Path import csv from order_utils import calculate_payable from report_utils import summarize_by_channel path = Path("data") / "orders.csv" valid_orders = [] with path.open(encoding="utf-8-sig", newline="") as file: for row in csv.DictReader(file): try: row["实付金额"] = calculate_payable(row) except (KeyError, ValueError) as error: order_id = row.get("订单号", "未知订单") print(f"跳过{order_id}：{error}") continue valid_orders.append(row) summary = summarize_by_channel(valid_orders)
关键分工：main.py 负责流程，order_utils.py 负责业务计算，report_utils.py 负责渠道汇总。模块拆分不应改变有效订单的计算结果。
